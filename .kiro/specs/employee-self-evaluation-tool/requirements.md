# Requirements Document

## Introduction

The Employee Self-Evaluation Tool is a web-based application that helps employees craft polished, compelling self-reflection write-ups for mid-year and end-of-year performance reviews. The system references the company's career expectations for an employee's specific level and practice area, then uses AI to automatically frame the employee's contributions across four evaluation pillars. The initial proof of concept targets Sr. Principal level employees in Client Delivery.

The tool guides the employee through a streamlined process: they select a review period, write a single free-form reflection describing their achievements and contributions, and the system automatically maps that input to the four evaluation pillars — generating a structured, professional write-up ready for submission. The employee can then review and revise each pillar section individually.

## Glossary

- **Employee**: The user of the tool; the person completing their self-evaluation.
- **Self-Evaluation**: A structured written reflection submitted by an employee describing their contributions, growth, and impact during a review period (mid-year or end-of-year).
- **Review Period**: Either mid-year (covering roughly the first half of the calendar/fiscal year) or end-of-year (covering the full year or second half).
- **Level Expectations**: The company-defined criteria describing the behaviors, skills, and impact expected of an employee at a given career level and practice area. For the POC, this covers Sr. Principal in Client Delivery.
- **Pillar**: One of four defined areas of evaluation that together constitute the full performance framework. Each pillar has its own set of level expectations.
- **Achievement**: A specific accomplishment, contribution, project outcome, or behavior the employee provides as input.
- **Reflection**: A broader narrative the employee provides describing their experience, growth, or challenges during the review period.
- **Write-up**: The final, polished self-evaluation narrative generated by the system, structured by pillar and ready for submission.
- **System**: The Employee Self-Evaluation Tool web application.
- **POC**: Proof of Concept — the initial scoped version targeting Sr. Principal level in Client Delivery.

## Requirements

### Requirement 1: Review Period Selection

**User Story:** As an employee, I want to select the review period (mid-year or end-of-year) at the start of my session, so that the system tailors the write-up framing appropriately.

#### Acceptance Criteria

1. THE System SHALL present the Employee with exactly two choices — "Mid-Year" and "End-of-Year" — as the first and only interactive element available at the start of each session, with no other input fields or navigation available until a selection is made.
2. WHEN the Employee selects a review period, THE System SHALL store the selection for the duration of the current session and display a visible confirmation of the selected period (e.g., a label or badge) that persists throughout the session.
3. WHEN the Employee selects a review period, THE System SHALL apply that selection to all subsequent prompts and the final write-up (e.g., mid-year write-ups frame contributions as progress to date; end-of-year write-ups frame contributions as full-year achievements).
4. IF the Employee has not selected a review period and attempts to navigate forward, THEN THE System SHALL display a message indicating that a review period must be selected before continuing, and SHALL NOT advance to the next step.

---

### Requirement 2: Level Expectations Reference

**User Story:** As an employee, I want the system to reference my level's career expectations when generating my write-up, so that my self-evaluation is aligned with what is actually being assessed.

#### Acceptance Criteria

1. THE System SHALL load and make available the Sr. Principal – Client Delivery level expectations content across all four pillars before the Employee begins writing their input.
2. IF the level expectations content fails to load AND the error message is successfully displayed to the Employee, THEN THE System SHALL NOT allow the Employee to proceed until the content is successfully loaded or the Employee explicitly chooses to proceed without it; IF the error message itself cannot be displayed, THEN THE System SHALL NOT block Employee progression.
3. WHEN generating the final write-up for each pillar, THE System SHALL reference the level expectations for that pillar to ensure the generated content addresses the defined behavioral and impact criteria.

---

### Requirement 3: Free-form Input

**User Story:** As an employee, I want to write all my achievements and reflections in a single text area, so that I can describe my contributions naturally without being guided through individual pillars.

#### Acceptance Criteria

1. WHEN the Employee advances past review period selection, THE System SHALL display a single free-form text area where the Employee can write all their achievements, contributions, and reflections for the review period.
2. THE System SHALL accept free-text input of up to 10,000 characters in the free-form text area and SHALL reject submissions that exceed this limit.
3. WHEN the Employee enters text, THE System SHALL display a live character count indicator that updates per keystroke, showing the current count and the 10,000-character limit.
4. IF the Employee's input reaches or exceeds the 10,000-character limit, THEN THE System SHALL visually indicate the limit has been reached (e.g., red counter) and disable the submission control until the character count is reduced below the limit.
5. IF the Employee attempts to submit input that contains only whitespace characters, THEN THE System SHALL treat that input as empty and display a message that at least some content is required before generating.
6. THE System SHALL display a "Generate Write-up" button that becomes enabled only when the input field contains at least 1 non-whitespace character.

---

### Requirement 4: Write-up Generation

**User Story:** As an employee, I want the system to automatically map my input to the four evaluation pillars and generate a polished write-up, so that I don't need to manually organize my contributions by pillar.

#### Acceptance Criteria

1. WHEN the Employee submits their free-form input, THE System SHALL analyze the input against the level expectations for all four pillars and generate a write-up section for each pillar (Client Delivery, Leadership, Business Development, and Firm Contribution) — mapping the employee's contributions to the most relevant pillars automatically.
2. WHEN generating the write-up, THE System SHALL produce content written in first-person voice, using complete sentences, formal vocabulary, and without slang, casual expressions, or contractions.
3. WHEN generating the write-up for each pillar, THE System SHALL produce content that references specific achievements or reflections drawn directly from the Employee's submitted input and addresses at least one behavioral demonstration or measurable impact as defined in the level expectations for that pillar.
4. WHEN generating the write-up, THE System SHALL produce each pillar section at a length of 150–350 words; a four-pillar write-up SHALL result in a complete document of 600–1,400 words.
5. IF a pillar has insufficient or no relevant content in the Employee's input to generate a meaningful section, THE System SHALL generate a brief placeholder section noting that limited information was available for that pillar, rather than fabricating specifics.
6. IF write-up generation fails due to a service error, THEN THE System SHALL display a descriptive error message identifying the failure and offer the Employee the option to retry without losing any previously entered data.

---

### Requirement 5: Write-up Review and Editing

**User Story:** As an employee, I want to review the generated write-up one pillar at a time and request revisions with additional information, so that the final output accurately represents my contributions.

#### Acceptance Criteria

1. WHEN the write-up is generated, THE System SHALL display each pillar section one at a time in a navigable, readable view with the pillar section clearly labeled.
2. THE System SHALL provide navigation controls (e.g., "Previous" / "Next" pillar) so the Employee can move between all four pillar sections.
3. THE System SHALL provide a revision input field adjacent to each pillar section, accepting up to 1,000 characters of additional context, corrections, or new information.
4. WHEN the Employee submits a revision request for a pillar section, THE System SHALL regenerate only that pillar section incorporating the revision feedback and any additional information provided, SHALL guarantee successful completion of regeneration within 30 seconds, and SHALL display an error if the time limit is exceeded; all other pillar sections SHALL remain unchanged.
5. WHEN a pillar section is regenerated, THE System SHALL preserve the most recent prior version of that section and provide a "Revert" control that restores it, replacing the newly generated version.
6. IF section regeneration fails due to a service error, THEN THE System SHALL display an error message for that section, retain the current version of the section, and offer the Employee the option to retry.
7. THE System SHALL provide a "Copy to Clipboard" action that copies the full write-up as plain text, and a "Download" action that saves the write-up as a `.txt` or `.md` file to the Employee's device.

---

### Requirement 6: Session Persistence

**User Story:** As an employee, I want my progress to be saved during a session, so that I do not lose my work if I navigate away or refresh the page.

#### Acceptance Criteria

1. THE System SHALL automatically save the Employee's free-form input and any generated write-up to browser local storage after each input change event, without requiring any save action from the Employee.
2. WHEN the Employee returns to the application after navigating away or refreshing, THE System SHALL detect a saved session that is no more than 7 days old and offer the Employee the option to restore it or start a new session.
3. IF the Employee chooses to restore a session, THEN THE System SHALL reload all previously entered input, any generated write-up, and return the Employee to the same workflow step they were on when they left; IF the saved session data is corrupt or incomplete, THEN THE System SHALL display a warning and offer to start a new session instead.
4. WHEN the Employee selects "Start Over," THE System SHALL display a confirmation dialog explaining that all saved data will be permanently deleted, and SHALL only clear saved session data and return the Employee to the review period selection screen after the Employee confirms.
5. WHEN a generated write-up is present in the current session and the Employee initiates a new session, THE System SHALL display a confirmation dialog warning the Employee that the existing write-up will be lost before clearing the session.
6. IF browser local storage is unavailable or full, THEN THE System SHALL display a persistent warning banner informing the Employee that session data cannot be saved and that they risk losing their progress if they navigate away.

---

### Requirement 7: Input Validation and Error Handling

**User Story:** As an employee, I want the system to handle errors gracefully and validate my inputs, so that I always know what is expected of me and my session is not disrupted.

#### Acceptance Criteria

1. IF a write-up generation request fails due to a service error, THEN THE System SHALL display a descriptive error message identifying the nature of the failure and offer the Employee the option to retry without losing any previously entered data.
2. WHEN the Employee enters input in the free-form text area, THE System SHALL display a live character count indicator that updates per keystroke, showing the current count and the 10,000-character limit.
3. IF the Employee's input reaches or exceeds the 10,000-character limit, THEN THE System SHALL visually indicate the limit has been reached (e.g., red counter) and disable the submission control until the character count is reduced below the limit.
4. IF the Employee enters input consisting entirely of whitespace characters, THEN THE System SHALL treat that input as empty and apply the same validation behavior as an empty field.

---

### Requirement 8: Accessibility and Usability

**User Story:** As an employee, I want the tool to be easy to use and accessible, so that I can complete my self-evaluation efficiently regardless of ability or device.

#### Acceptance Criteria

1. THE System SHALL meet WCAG 2.1 Level AA accessibility standards for all interactive components and generated content.
2. THE System SHALL support all core evaluation workflows — including navigation, text input, and form submission — on desktop browsers (Chrome, Firefox, Edge, Safari) at viewport widths between 1024px and 2560px.
3. WHILE the Employee is in the evaluation workflow, THE System SHALL display a progress indicator showing which step the Employee is currently on.
4. WHEN the Employee navigates between pillar sections in the write-up view or experiences any workflow interruption (including page refresh, browser tab restoration, or temporary network disconnection), THE System SHALL preserve all previously entered form inputs and generated write-up content without loss.
5. THE System SHALL support all core evaluation workflows on mobile and tablet browsers at viewport widths between 320px and 1023px.
